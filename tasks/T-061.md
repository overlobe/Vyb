## Goal

Ordna gives every repo its own board, and Vyb shows that board for the
active profile. Once you have more than a handful of profiles there is
no way to see where things stand across them without opening each
Kanban in turn.

Add a **Task Overview**: one view across every profile that answers
"where is each project at?" and "what could I pick up in the next
hour / day / week?". It is a human-readable status of each project,
not a giant combined Kanban. Detail stays in each repo's own board,
one click away.

## Background

- Ordna is one board per directory by design: `createContext(cwd)`,
  `runWeb({ cwd })` and `watchTasks(ctx)` all bind to a single
  directory. There is no registry of projects in Ordna.
- `@frehilm/ordna-core` is a plain library, so aggregating is cheap:
  N × `createContext` + `listTasks` (+ `watchTasks` later). Every
  storage mode (file / hybrid / namespace) answers the same API.
- Vyb already has the project registry: each `Profile` has a
  `workingDirectory`, and profiles are grouped into `Workspace`s. No
  new config is needed.
- The same "walk every profile directory" plumbing is wanted by
  **T-057** (multi-repo git status), and the overview is a sibling of
  **T-053** (workspaces) and **T-054** (notifications centre).

## Design

**Where it lives.** It's built in Vyb first. The aggregation logic is a
standalone main-process module (`src/main/task-overview.ts`) with no
Electron dependencies beyond the caller, so it could move into
`ordna-core` later (e.g. a `listAcrossRoots()` helper, or an
`ordna ls --all` command reading a registry) if Ordna wants it.

**Project list.** Saved profiles, de-duplicated by resolved working
directory (that is the directory Vyb's Kanban uses as Ordna's cwd).
Several profiles on the same directory become one project that lists
every profile name. Parallel-agent worktrees are not projects.

**Strictly read-only.** The overview must never create Ordna state in
a repo that doesn't have it:

- file / hybrid: only opened when the tasks directory already exists
  (backend `init()` would otherwise `mkdir` it).
- namespace: only opened when `refs/ordna/state` already exists
  (`init()` would otherwise write it), and the backend is always
  `dispose()`d after listing so no auto-fetch timer is left running.
- Directories with no config and no tasks are reported as "no Ordna"
  and hidden by default.

**Status buckets.** Each repo can define its own `statuses`, so names
are mapped by position:

| Ordna status | Bucket |
|---|---|
| first status (e.g. `todo`) | open |
| last status (e.g. `done`) | done |
| anything in between | in progress |
| `archived` | archived (hidden) |
| not in the list | open (flagged as unknown) |

An open task is **ready** when every `depends_on` task in the same repo
is done, otherwise **blocked**. An in-progress task not updated for 14
days is **stalled**.

**Per-project summary.** One human-readable line, e.g.
"2 in progress · 4 ready to start (1 high) · 1 blocked · last activity
3 days ago", plus the checked-out branch, a stacked count bar, and a
marker for tasks with a running parallel agent.

**Views.**

- *Projects*: cards grouped by workspace, sorted by most recent
  activity. Expand a card for its open and in-progress tasks.
  "Open board" jumps to that profile with its Kanban shown.
- *Tasks*: a flat list across every project, filterable by bucket
  (ready / in progress / blocked / stalled / all open), priority and
  free text, sorted by priority then recency.
- Scope toggle: current workspace or all workspaces.

## Acceptance Criteria

- [x] View → Task Overview (`CmdOrCtrl+Shift+K`) opens the overview.
- [x] Every saved profile with Ordna tasks appears once, grouped by
      workspace. Shared directories are de-duplicated.
- [x] Repos without Ordna data are never written to, and are hidden.
- [x] Namespace-mode repos are listed without leaving fetch timers
      running.
- [x] Status names are mapped into open / in progress / done buckets
      per repo. Ready, blocked and stalled are derived.
- [x] Each project shows a one-line plain-language summary and its
      current branch.
- [x] Flat task list with bucket, priority and text filters.
- [x] "Open board" switches workspace if needed, selects the profile
      and shows its Kanban.
- [x] A broken repo (bad config, unparsable task) shows an error on its
      own card and doesn't break the rest.
- [ ] Live updates via `watchTasks` (prototype refreshes on open, on
      window focus and on demand).
- [ ] "Send to agent" from the overview, routed to the owning profile.
- [ ] Shared registry module with T-057.

## Open Questions

- [ ] Should the aggregator (and maybe a project registry or
      `ordna ls --all`) live in `ordna-core`, so it works outside Vyb?
- [ ] Should status mapping be an Ordna config key (e.g.
      `statusBuckets:` in `.ordna/config.yaml`) rather than inferred
      from position?
- [ ] File / hybrid boards depend on the checked-out branch. Should the
      overview read the default branch instead (`git show
      main:tasks/…`), or just label the branch as it does now?
- [ ] Tasks being worked on in a parallel-agent worktree only change
      status in the main tree after merge. Is the "agent running"
      marker enough?
- [ ] Is 14 days the right "stalled" threshold, and should it be a
      setting?
- [ ] An export (JSON / markdown) of the overview, for feeding
      personal dashboards or notes?

## Notes

- Status detection for `ordna:` PTYs is unaffected; the overview
  spawns no PTYs and no Ordna web servers.
- Cost: one `git rev-parse` per project plus one `listTasks`, run with
  a small concurrency limit. Fine for dozens of profiles. Live watching
  should stay limited to the active workspace.
